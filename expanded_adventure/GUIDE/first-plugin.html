Your first plugin

From an empty folder to a duel on your own island, in seven steps. You need the game, Python 3 and a text editor; nothing else is installed.

  1. Make the skeleton

    Open a terminal in the game folder (the folder that holds tools/) and ask the tool for a new plugin:

    $ python3 tools/adventure_plugin.py new my_isle --id my_isle --name "My Isle"
# Windows, in the same folder: python tools\adventure_plugin.py new my_isle --id my_isle --name "My Isle"

    On Windows, type python (or py) instead of python3 and \ in paths, as the second line shows; every other adventure_plugin.py command on these pages works the same way.

    It writes a folder my_isle/ that already loads and plays: a manifest, an island recipe, a port and a castle with small placeholder map pictures, one quest, a finale, a foe for each, and the words for all of it. --id is the plugin’s identity for ever (see below); --name is what players read.

  2. Edit it

    Everything is plain JSON and text. Start with the manifest, plugin.json:

    FieldRule
    plugin_format1. Required.
    api_version1, the plugin API this guide describes. Required. A plugin asking for a newer API than the game reads is refused with “a newer game is needed”.
    id1 to 40 lower-case letters, digits or _, a letter first; never mainland. Required. It names your land in every save, begins every picture key (my_isle_harbor) and every button the game makes for it. Never change it once players have it.
    nameAt most 100 characters. Required. The plugins window’s title for it.
    version1 to 4 numbers joined by dots, like "1.0.0". Required.
    minimum_game_versionOptional, numbers and dots. An older game refuses the plugin and says which version it needs.
    authorsA list of 1 to 16 names. Required.
    descriptionOne line of at most 300 characters for the plugins window. Required.
    license, learning_noteOptional text, at most 4,000 characters each. Both are shown in the plugins window.
    requiresOptional: {"card_packs": [{"id": "pack-2", "min_version": "1.0"}]}, at most 16 packs, each one the game knows. Pack 1 is never part of an adventure and is refused here. min_version is the oldest version of the pack the plugin works with; with an older one installed, the plugin says it needs that version or newer. With no packs, the plugin is on whenever it is ticked, and its cards must all be base-game cards.
    regionRequired: title (required, at most 100 characters), castle_name, salt (0 to 2147483647: which island the terrain generator makes), mana_links (whether the island’s places can take mana links; the Refuge’s cannot), palette (a built-in palette’s name or a palette object; The world).
    filesLeave it out. export writes it into the zip it makes: every file’s SHA-256.

    A field the manifest does not know refuses the plugin, so a typo is named instead of being ignored. Then shape the island in world.json and places.json, the story in quests.json, the duels in foes.json and rewards.json, and every word in text.json.

  3. Validate

    $ python3 tools/adventure_plugin.py validate my_isle
# Windows, in the same folder: python tools\adventure_plugin.py validate my_isle

    The same checks the game makes, in the same order (Testing). Every problem is a line naming the file and the place in it, for example quests.json: quests[0].foe: foes.json has no tithe_colector. A JSON file that does not parse is named with the line of the mistake, counted from 1. Fix, and run it again until it says the plugin is valid.

  4. Export

    $ python3 tools/adventure_plugin.py export my_isle --out dist
# Windows, in the same folder: python tools\adventure_plugin.py export my_isle --out dist

    This writes dist/my_isle.zip (dist/ in the current folder is also where it goes without --out): one top folder, the files in sorted order with fixed times, and a manifest carrying every file’s SHA-256 in its files list. The zip is checked again as it is written. Your folder is left as it was. The hashes let the game notice a file changed after export; they are integrity, not a signature.

  5. Install

    Copy the zip into the plugins folder: the one Options shows on its Adventure plugins folder line, expanded_adventure in the game’s user folder unless you moved it. While you work, the unpacked folder may sit there instead: a folder holding plugin.json is read the same way as a zip.

    One copy at a time

    In one folder the zips are read before the folders, and the first copy of an id wins. An exported my_isle.zip beside your working my_isle/ folder would be the one played, and the window would list the folder as a copy not used. That is why export refuses an --out that is the folder holding your plugin’s folder: export to dist, as above.

  6. Tick it at the Embark

    Start a new adventure. At the bottom of the card-pack list press Expanded adventure plugins.... The window of that name lists every plugin found, with its version, authors, description and learning note, and a line for each card pack it needs, such as Needs Pack 2 · Fallen Empires — ticked (or not ticked, not installed). Tick yours; its packs are ticked with it. A refused plugin is greyed with every problem the checks found. Rescan reads the folders again after you change something, Open folder opens the plugins folder, and OK closes the window.

  7. Play

    Embark. On the mainland your island’s ship waits at an anchorage on the coast near where the hero starts, marked Ship: your region title. Walk onto it, read your port’s pane and sail. Your castle, towns and quests are on the island; the ship always takes the hero home.

    The island is made the first time a hero sails there, and from then on it is part of that adventure’s save. To see a change to world.json, start a new adventure, or sail with one that has not been there yet. Changes to words, foes, rewards and pictures show after Rescan or the next start of the game, in new adventures and saved ones alike. A change to the quests or the town slots reaches a saved adventure only within the rules of Saves and compatibility: a saved land the new version cannot read is kept as it was and does not sail.

The smallest working content

The checks ask for a few things in every plugin. Knowing them saves a round of validate:

  • world.json: generator: "island", at least one town in towns.list, and a dungeon with a name.
  • places.json: a port and a castle marker, each with a name, a picture and at least one pane.
  • quests.json: the town words (town.line, town.action, town.thanks), at least one quest whose last step is a duel, a finale with its done_flag declared in flags, and the two task rows (tasks.finale, tasks.rewards).
  • foes.json: every foe a quest or the finale names.
  • text.json: every key the other files name.
