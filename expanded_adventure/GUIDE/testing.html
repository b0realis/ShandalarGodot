Testing

Three tools, from the quickest to the closest to play: the validator, the Expansion Lab, and the game itself.

The checks

The package stage is the strictest, and it is about safety:

  • A zip holds every file under one top folder (any name; the id is the manifest’s), with plugin.json in it. Plain zip only: no zip64, no encryption, entries stored or deflated, no two entries with one name (letter case ignored), no symbolic links. A folder: no symbolic links.
  • Paths: at most 200 characters, relative, with / only, no \, :, control characters, or empty, . or .. parts.
  • Files of these kinds only, by extension, letter case ignored:
    • .json
    • .txt
    • .md
    • .png
    • .jpg
    • .jpeg
    • .webp
    • .ogg
    A JSON, .txt or .md file is at most 1 MiB of UTF-8, and JSON nests at most 32 deep; an OGG is Ogg Vorbis and at most 16 MiB; a picture’s first bytes name its kind, and it is at most 4,096 pixels a side.
  • At most 512 files and 32 MiB in all, the zip itself no bigger.
  • Litter other systems leave is passed over, never read nor counted: any name beginning with ., a __MACOSX folder, Thumbs.db and desktop.ini.

The validator

$ python3 tools/adventure_plugin.py validate my_isle
# Windows, in the same folder: python tools\adventure_plugin.py validate my_isle
my_isle: valid (plugin my_isle 0.1.0).
$ python3 tools/adventure_plugin.py validate broken_isle
broken_isle: refused at the content stage (1 problem).
quests.json: quests[0].foe: foes.json has no smugler.

It takes a folder or a zip. --json prints one object instead (valid, stage, problems, notes, id, name, version), for your own scripts. The tool reads the game’s own schema, game/adventure/plugins/schema_v1.json, and the game’s card lists, so run it from the game folder (a release or a checkout), or name one with --game DIR, before or after the command. A copy of the tool on its own stops with exit 2 and says where to run it. Where the schema is found but no card lists, it adds the note “Card names were not checked” and checks the rest as usual.

The tool’s other commands: info prints the manifest and what the plugin holds (towns, quests, foes, texts, files), info --json the same as one object; compat OLD NEW compares two versions for saves; guide rewrites this guide’s Reference page from the schema, and guide --check only says whether it is up to date. Every command exits 0 when done, valid or compatible, 1 when refused or incompatible, and 2 on a usage error; --version prints the game version and plugin API it checks for.

The Expansion Lab

In a source checkout of the game, the Expansion Lab plays a plugin headless: for each world seed it sails out and back, and checks the terrain, the objectives, the saves, the mana links and that a dormant plugin leaves nothing behind. With --games it also duels your foes and roaming decks with two reference decks at several life totals.

$ ./tools/expansion_lab.sh --out lab-my_isle --plugin path/to/my_isle --seeds 5,37,48271

--plugin takes a folder or a zip. The run copies it into plugin/ in the results folder, the only plugins folder it sees, and deletes the copy at the end; the plugin’s id is the region, and it must pass the game’s checks first. It needs the card packs your plugin requires (a development run finds them through SHANDALAR_PACK_N). In the middle of a trip it takes away what the land needs, its card pack or, for a plugin that needs none, the plugin itself, and the hero must still sail home. For every seed it then plays your land to its end on the game’s own results, with no duel fought: every quest step by step, the rewards claimed, the finale won, and the adventure saved and read back on the island and at home; the land must come back neither held nor damaged. --games 1 also plays your plugin’s duels. It writes results.json, report.txt and engine.log, exits 0 when every check passed, 1 when one failed or the plugin was refused (with its problems), 2 for a path that is not there, and never touches your own profile.

The loop in the game

  1. Put the unpacked folder in the plugins folder, with no exported zip of it there.
  2. Start a new adventure, open Expanded adventure plugins... and look at your row: a refused plugin is greyed with every problem, exactly as the validator prints them. Tick it.
  3. Play to the part you are working on. Save in a slot before a duel or a step, so you can come back to it.
  4. Change words, foes, rewards or pictures. Start the game again, or press Rescan in the Embark’s plugins window, then load the slot.
  5. For a change to the quests or the town slots, follow Saves and compatibility: a slot whose land the new version cannot read loads with that land held, so test such changes in a new adventure.
  6. For a change to world.json, start a new adventure: a made island is part of its save.

Before you share it

  • validate says valid, in the game folder, so the card names were checked.
  • export made the zip you share; nothing was changed in it afterwards.
  • compat against the version players have says compatible.
  • The plugin was played from the Embark to its finale in a fresh adventure.
  • README.txt says what it needs and what it is; LICENSE.txt says how it may be shared; every picture is your own or licensed for it.
