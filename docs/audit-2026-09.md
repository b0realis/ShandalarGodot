# Full audit, bug hunt & optimization pass — 2026-09

Date: 2026-08-31. Scope: **all 788 implemented cards** re-read against the
Scryfall oracle snapshot in `cards/data/` and against their mage-go
counterparts, plus a line-by-line hunt through every engine subsystem added
since the previous review (`docs/code-review-2026-08.md`, written at 648
cards) — targeting and copying, the CR 613 layer pipeline, zones/tokens/
control/phasing/face-down/ante, combat, mana and restricted mana, poison,
the random-effect subsystem, the stack/priority/trigger/state-based-action
machinery — and a measured optimization pass on the continuous-effects hot
path.

Authority, unchanged from the earlier audits: **the oracle text wins**
(`cards/data/*.json` is canonical); mage-go is the mechanics reference, and
where mage-go itself deviates from oracle and we match oracle, the row says
"mage-go deviates" and nothing changes on our side.

Every fix landed test-first: the pin named in each row failed before the
change and passes after. Pins live in
`tests/unit/test_audit_2026_09.gd` (engine) and
`tests/cards/test_audit_2026_09{,_a,_b,_c,_d}.gd` (cards).

Suite: **1090 tests → 1215 tests, all passing** (24 293 → 27 038 asserts,
77 → 83 scripts; ~12 s). A five-deck round robin (300 games per pair, seed
4242) finishes with **0 stalled games**.

### Second-opinion pass over this change set

The change set above was then re-reviewed against the code (no git history
exists to diff, so the table itself was the change list). That review found
four real defects introduced or missed by the first pass — recorded here
because "the fix was wrong" is exactly the kind of thing an audit should say
out loud:

| Area | Issue | Severity | Status | Pinned by |
|---|---|---|---|---|
| Combat (CR 509.1h) | The blocked-status fix broke **False Orders**, whose printed middle sentence is an explicit EXCEPTION to it: "creatures it was blocking that had become blocked by only that creature this combat become unblocked". The card became strictly harmful — it blanked one of your own attackers — and its old test had been rewritten to enshrine that. `remove_from_combat` now takes an opt-in `unblock_solo_attackers`, which only False Orders passes. | HIGH | fixed | `test_only_false_orders_unblocks_the_creature_it_freed`, `test_false_orders_re_points_a_blocker` (restored) |
| Continuous effects (CR 613.8) | The layer-4 pass ran TWICE to resolve dependencies, on the claim that its statics "assign rather than accumulate" — but three of them do `cur_types \|= CREATURE`, which nothing revokes. Kormus Bell plus Blood Moon left a Badlands as a 1/1 black creature that was also a Mountain. Replaced with an ordering that is right by construction: land RETYPERS (`changing_land_types`) run before the animators that read those types, once each. | MEDIUM | fixed | `test_a_retyped_land_is_not_animated_by_its_old_type` |
| Continuous effects (CR 613 layer 6) | "Loses all abilities" was claimed to be decided in the layer-4 pass; it was not, so a silenced Kormus Bell kept animating Swamps. Ability REMOVAL now runs in its own first pass (`silencing_abilities`), and every later pass skips a silenced source. | MEDIUM | fixed | `test_titanias_song_silences_a_type_changing_static` |
| Continuous effects (CR 613.4) | Counters (layer 7d) ran AFTER the general statics, so **Meekstone** read a Clockwork Beast's printed power 0 and never locked it. Counters now run between the base-P/T setters and the anthems — the setters still cannot wipe them, and the anthems are additive. | MEDIUM | fixed | `test_meekstone_sees_counters_a_creature_entered_with` |

It now asks the blocked STATUS, and so does the AI's Fog/firebreathing valuation. | LOW | fixed | (shares the blocked-status pins) |
| Zones | Three floating passes (pumps, block restrictions, P/T switches) applied to PHASED-OUT permanents, which pass 1 never resets — a Giant Growth on an Oubliette'd creature added +3/+3 on every recalculation and a Transmutation oscillated. | LOW | fixed | (guarded in `continuous.gd`; scrubbed on phase-in either way) |

### mage-go deviations found (ours correct — recorded for reference)

- **Clockwork Avian / Colossus of Sardia / Cyclopean Tomb**: mage-go's
  `WithUpkeepOnly()` checks the step but not whose turn it is.
- **Mana Matrix / Planar Gate**: mage-go's cost reduction is not
  controller-scoped, so it discounts BOTH players' spells.
- **Angry Mob**: mage-go models the characteristic-defining ability as a
  boost on a 0/0 body; oracle SETS power and toughness (layer 7b).
- **Spell Blast**: mage-go counters whenever X ≥ the target's mana value;
  oracle demands equality.
- **Fireball**: mage-go is a single-target burn — no "costs {1} more for
  each target beyond the first", no divided damage.
- **Blazing Effigy, Imprison, Divine Intervention, Knowledge Vault,
  Visions, Winter Blast, Takklemaggot**: all carry explicit `XXX`/`TODO`
  gaps upstream that we implement.
- **Reset / Teleport**: mage-go has no cast-timing rider at all.
- **Veteran Bodyguard**: mage-go redirects ALL combat damage; oracle says
  "by unblocked creatures", which we enforce.
- **Obelisk of Undoing**: mage-go checks control only; oracle says "you
  both own and control".
- **The Abyss**: mage-go shares the non-targeting shortcut we just fixed.

## Optimization

The continuous-effects recalculation is the hot path, as expected — but the
measurement decided what to do about it. An instrumented copy of the tree
(never the shipped one) timed each subsystem over a fixed-seed Deck Lab run:

| Subsystem | Calls (300 games) | Time | Share of wall clock |
|---|---|---|---|
| `ContinuousEffects.recalculate` | 52 883 | 0.94 s | 29 % |
| — of which `CardInstance.reset_characteristics` | 587 000 | 0.61 s | 19 % |
| — of which the static passes | — | 0.13 s | 4 % |
| `check_state_based_actions` | 60 549 | 0.24 s | 7 % |
| `dispatch_event` | 99 442 | 0.21 s | 7 % |
| `all_battlefield` (cached; 8 559 rebuilds) | 395 936 | — | — |

So the per-permanent reset dominated the pipeline, and tapping lands
dominated the call count (12 038 of the 52 883 recalculations came from
`tap_for_mana` alone). Three changes, all behaviour-preserving:

1. **`ManaCost.color_mask()` is memoised.** A cost is immutable after
   parsing, and the mask is read for every permanent on every
   recalculation — it was recomputed by iterating a Dictionary each time.
2. **`reset_characteristics` refills its five live lists with
   `Array.assign`** (one call) instead of `clear()` + `append_array()`
   (two), on the engine's hottest line.
3. **A tap or untap skips the recalculation when the battlefield carries no
   static ability at all.** The only way a tap can change any current
   characteristic is through a static that reads tapped state (Castle,
   Meekstone); every other input to the pipeline is blind to it, and the
   game/player fields the pipeline resets are written only by statics. With
   no statics on the board the pass is provably a no-op, so only the UI
   refresh signal is emitted. Any path that adds a static recalculates on
   its own.

### Measurements

Deck Lab, `big_green.deck` vs `black_red_raiders.deck`, **1000 games, seed
12345, `--jobs 1`** (single-threaded, so the number is the engine and not
the scheduler):

| Build | Time | games/s | Result |
|---|---|---|---|
| A — start of this pass (788 cards) | 10.0 s | 100 | 453–547 |
| B — A **plus** every correctness fix in this document | 10.1 s | 99 | 453–547 |
| C — B **plus** the three optimizations (shipped) | **9.2 s** | **109** | 453–547 |

* B → C: **9 % faster** (−8 % wall time); recalculation calls −19 %,
  time inside the recalculation −27 % (0.94 s → 0.69 s per 300 games).
* A → B: the ~30 rules fixes cost about 1 % — the added work (a layer-4
  pass, an Aura legality state-based action, deferred combat SBAs) is
  bounded by lists that are almost always empty.
* **Determinism:** all three builds produce the byte-identical 453–547
  split and identical per-game turn counts. That is the evidence the
  optimizations changed no decision anywhere — and, for the correctness
  fixes, that none of them reaches this matchup's card pool.
* Repeatability: nine consecutive runs of build C (before and after the
  second-opinion fixes) reported 9.2–9.3 s / 107–109 games/s, with the same
  453–547 split every time. Measure on an idle machine: with four other
  Godot processes running, the same command took 12.9 s for the identical
  result.

A five-deck round robin (10 matchups × 300 games, seed 4242) finishes with
**0 stalled games** — the check that matters most after the combat changes,
since the Festival/Juggernaut deadlock this pass fixed was exactly the kind
of hang that shows up there first. The same round robin run twice at
`--jobs 4` and `--jobs 7` produces byte-identical per-matchup results, which
is the second half of the determinism claim: the thread count changes only
the wall clock.

Nothing here trades correctness for speed: two of the three changes are
memoisation of values the engine already recomputed, and the third rests on
a stated invariant with a test behind it.

## Presentation layer (`game/`) — reported, not touched

`game/` was read but deliberately left alone (another session owns it).
Consequences of the engine changes made here:

- **New refusal strings** the UI shows verbatim: `"activate only during
  your turn"` (Cyclopean Tomb, Clockwork Avian), `"illegal target for
  'target artifact with mana value X'"` and the Spell Blast equivalent
  (previously these casts were allowed and did nothing), `"only during your
  main phase with an empty stack"` (Illusionary Mask), and the Eternal
  Flame target slot now demands a player target.
- **A blocked attacker stays blocked.** Removing or regenerating a blocker
  no longer lets the attacker through (CR 509.1h). A duel screen that
  colours "unblocked" attackers from `combat.blocks` should read
  `combat.blocked_attackers` instead, or it will show a creature as
  unblocked that will deal no damage.
- **Fellwar Stone now asks for a colour** through `DecisionAgent.choose_color`
  — `HumanAgent` answers with the heuristic, so a human player never sees
  the prompt. *(SUPERSEDED 2026-09-01, duel-todo.md §1.3: the human DOES see
  it. The ask moved out of the card into `MtgGame.tap_for_mana` via
  `ManaAbility.color_options`, which is where the duel can be held open for
  it — the card had been asking after the Stone was already tapped, and
  asking twice.)* Same for the Takklemaggot jump and the Preacher gift, which
  now ask the VICTIM's agent.
- **Poison has no UI at all** (`grep poison game/` is empty): a duel lost to
  Marsh Viper, Pit Scorpion or a Serpent Generator Snake ends with no
  visible clock.
- **The mana readout ignores restricted mana**
  (`duel_screen.gd` uses `pool.amount_of(color)`), so tapping Mishra's
  Workshop shows an empty pool and the castable-card highlight never lights
  up off it; the X dialog ignores `cost.x_count`, restricted mana, colour
  substitutions and the North Star charge, and it bounds X with the
  unclamped surcharge (which the engine now agrees with — see the cost
  reduction row).
- **The duel screen's coin toss uses the global `randi()`** and
  `game.setup(...)` is called without a seed, so a UI duel cannot be
  reproduced from a bug report even though the engine can.

### Disposition of the UI findings

All of the above were verified against the code and FIXED the same day —
see `docs/duel-screen-design.md`, twenty-fifth pass, for what each change
was; every one is pinned in `tests/ui/test_duel_screen.gd`. Two of them
grew a small public engine API rather than re-deriving a rule in the UI
where it would drift: `MtgGame.can_afford(pid, data)` (the castable hint
now gets cast_spell's own answer, cost modifiers under the CR 601.2f
floor, restricted mana and substitutions included) and
`ManaPool.total_of(color)` (the honest per-colour total, restricted mana
included, for the readout).

One finding did NOT apply. The blocked-attacker note supposes the duel
screen colours attackers from `combat.blocks`; it does not — `grep
combat. game/` returns three sites, and the blocker flow works off a
local `_block_map` of the player's PENDING assignments plus
`combat.attackers` for the highlight. There is nothing reading
`combat.blocks` to correct.
