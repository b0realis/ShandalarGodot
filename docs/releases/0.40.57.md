# Shandalar 0.40.57

*"Just click on magic battle in main menu seems a bit sluggish?"* — the
owner, on 0.40.56. It was: the press on Magic Battle opened three
hundred deck files some six thousand times before the screen could be
drawn.

- **The setup screen reads each deck once.** `_scan_decks` reads the
  file, parses it for its cards and files it under its heading from the
  one text (`DeckList.from_text`, `DeckGroups.of_text`), and both deck
  pickers walk the groupings built there. The picker used to ask
  `DeckGroups.of` — which opens the file — for every playable deck
  under every heading, for each seat: 6,216 reads where 330 suffice.
- **One parse per deck where two were made.** A deck whose lenient
  parse noted no proxy parses identically under strict, so it is parsed
  once; the decks with proxies or a disabled pack are parsed twice as
  before.
- **Measured on the desk** (Xvfb, seven packs, 330 decks): 402 ms from
  the press to the screen's first frame became 148; a handheld, where a
  read out of the package is dearer, gains more.
- **Held by** `tests/ui/test_setup_screen.gd`: a read count
  (`DeckStore.reads`) of at most one per deck file for a fresh screen,
  and the lists the screen concludes unchanged.

Gate: 548 scripts, **8,262/8,262 tests, 370,341 asserts**, exit 0;
Python 415 (5 skipped).
