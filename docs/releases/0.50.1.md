# Shandalar 0.50.1

*"Expand the max player count on the tournament to 40 and establish a
togglable, modifiable basic table rules when you host the game."* — the
owner. Four orders in one version: the forty-entrant tournament, the
host's table rules, a review of the network code, and a game played
through the MCP server with the fixes it found.

- **Forty entrants.** A LAN knockout takes 2–40 players over up to six
  rounds (a forty-entrant first draw is eight played pairings and
  twenty-four byes); the host has sockets and sessions for the whole
  field reconnecting at once (88) and twenty rooms.
- **Table rules.** **Table rules…** on the Host Game page and on the
  tournament setup page sets the table's starting life (1–400) and the
  seven implemented rules forks — the Options screen's presets or any
  custom mix. The choice travels with the table: the Game Browser's row
  and the LAN advert carry a one-line brief, the waiting room, the
  opening card and the tournament hall name it, the referee's game plays
  under it. The standard table is what every host opened before (20 life,
  modern rules, mana burn on); the editor remembers your last table on
  this computer; an older saved tournament restores unchanged.
  Wire protocol **25** — every peer needs this build.
- **Network review.** Nine fixes: the connection headroom; a LAN advert
  measured against the packet (the last rows go instead of a reply no
  browser shows); a checkpoint backup that trusts its own digest and
  refuses an oversized file; tournament views that ride uncopied (forty
  copies of sixteen decks per command); a client that walks a config once;
  the rules brief written on the room once; four listings per LAN
  address; the organiser's chair taken back on a finished or cancelled
  event so it can be closed; discovery packets encoded, not stringified.
- **The referee and the MCP server.** A decision's hand no longer grows
  into the whole table (`Array(array)` is the same array); a deck
  report's own errors stay its own; the pilot cancels a payment whose
  tap put a trigger on the stack and casts the spell again once it
  resolved; `list_decks` finds the workspace wherever `--workspace` put
  it.
