# Shandalar 0.40.50

The second headset report: the trace worked — the Quest 3's laser click
reaches the game as a touch — and the rest of the start was gone from
Android's log before it was read. Now the game writes its own report.

- **The start report in the corner.** At every Android start the game
  writes `start_report.txt` into its shared-storage corner
  (`/sdcard/Android/data/com.b0realis.shandalar/files/`), line by line
  as the start goes: the version and the moment, the corner and its
  four folders, how long the tree took, the display's side, what the
  skin and the card packs said, and the first input event of each
  class. `adb pull` it at any time; it is the last start's.
  `adb logcat -d` after the fact had shown only the click: the main
  log buffer is a ring the headset's shell fills within minutes, and
  every line of the start was out of it.
- **The pack lines carry their cost**: `card pack: found … (sealed,
  40 ms)` or `(hashed, 8210 ms)` — what a sealed and a hashed start
  cost on this machine, in the log and in the report. `CardPacks` and
  `SkinPack` keep the lines they said (`report_lines`) for the report.
- **What the trace said**: the laser's click is `InputEventScreenTouch`
  from device 0 and the engine's mouse button emulated from it — the
  touch layer is the Quest's; `docs/handhelds.md` says so, shows the
  report, and reads the log live (`adb logcat -s godot Godot` before
  the start) rather than after.
- **`build_release.sh --quest`** ends with the package's
  `push_to_quest.sh`, not the old two push lines from before the game
  made its folders.
- No wire change: protocol 24 peers interoperate.
