# Shandalar 0.40.51

The third headset report: *"When i want to select a deck from the
dropdown menu in magic battle the menu does not appear."* Reproduced on
the desk in a test, fixed in the two pointer layers.

- **A tap that opens a menu leaves it open.** An `OptionButton` opens
  its menu on the press, and the Magic Battle deck list — 354 decks —
  is taller than the panel, so Godot fits the menu over the button
  itself. The touch layer's tap was a press and a release in one frame;
  the release went into the freshly opened menu, which chose the row
  under it (a deck the player never picked) and closed in the same
  frame — "the menu does not appear". A mouse is spared only because
  its press sets the engine's button mask, which makes a menu ignore a
  release inside 400 ms; an event a layer pushes never touches that
  mask. So a tap whose press opened a focused window sends no release:
  the menu has the finger's next tap, as a context menu always had.
- **The pad's A that opens a menu is let go.** The same press under the
  pad pointer hands the menu the pad while A is still down, and the A
  up never reached the layer — which held A for good and dropped the
  next A as a second copy of a press still down (on the Deck: the
  first click after choosing a deck did nothing). The layer lets that
  A go itself when its press opened a window.
- **Two tests pin it**: `test_touch_controls.gd` (a sixty-row menu
  fitted over its button: open after the tap, no row chosen, the next
  tap on a row chooses) and `test_pad_controls.gd` (A opens, the A up
  is the menu's, the D-pad chooses, the next A is a press again).
- No wire change: protocol 24 peers interoperate.
