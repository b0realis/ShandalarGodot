# Shandalar 0.40.22

- A fanned-out Deck Lab run (every run of 40 games or more) could lose
  its last slice: the parent took a worker's answer file for the slice's
  landing the instant the file existed, and a worker with a big slice
  opened the file seconds before it had finished writing. The parent
  then took the run for finished, killed that worker mid-write, read an
  empty file and replayed every game in-process — where the first
  thousand-deck tournament (430,000 games, 3 h 21 m) crashed with
  nothing written. A worker now writes under a working name and renames
  the file whole; the parent lands a slice only under its final name.
- A worker that dies is replaced by a fresh one for the same slice,
  three in all, while the other workers play on; the retried games are
  the same games with the same seeds. A slice no worker can finish stops
  the run (exit 1) naming the unplayed games and the one the last
  heartbeat was on, by pair and seed. A run is never replayed in-process
  any more.
- `--help` and the Lab README say so under `--procs`.
- No wire change: protocol 24 peers interoperate.
