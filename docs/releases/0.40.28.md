# Shandalar 0.40.28

- **`AGENTS.md`** — the contract for driving the headless tools from a
  script, a pipeline or an agent: the two channels (stdout the
  instrument, stderr the human), every tool's exit codes, the refusal
  envelope and its kinds, `--dry-run`'s plan keys, every output file
  with its keys (`results.json`, `sweep.json`, `decks.csv`), the house
  invariants (a sweep needs its control pair, `--no-elo` on a mined
  field, one run at a time) and a session in order. `CONTRIBUTING.md`
  stays the contract for editing.
- **The refusal as data.** Every refusal the Deck Lab or the AutoDeck CLI
  makes before a game or a deck — every exit 2, and the exit 1s a run
  can hit before it starts — now prints ONE line of JSON on stdout,
  `{"error": {"tool", "exit", "kind", "message", "flag", "suggestions",
  ...}}`, beside the unchanged prose on stderr. `kind` is the thing to
  branch on (`option`, `deck`, `packs`, `pool`, `out`; the AutoDeck's
  `sets`, `list`, `keep`, `vary`); `suggestions` carries what "did you
  mean" said — a flag once, even one that sits in both parser tables
  ("--gold or --gold" is gone).
- **`--dry-run`** in both tools: every check runs, then the plan is
  printed as JSON on stdout and nothing is played or written — the decks
  with their files and sizes, the matchups, the total games (a sweep's
  arms × pairs × games), seed, jobs and processes, the packs actually on,
  the output folder and a clock estimate labelled as the guess it is;
  the AutoDeck's plan adds the wish combinations, whether the run would
  roll a seed, whether `--out` already holds files (the `--force`
  question, answered before anything is cleared), the files it would
  write and the disk they take, and the `next:` line as data. Exit 0, no
  folder made.
- No wire change: protocol 24 peers interoperate.
