# Shandalar 0.40.49

The first headset report answered: the Quest 3 runs the panel, the skin,
the packs, the music and the laser's hover — once the folders in the
app's shared-storage corner are the game's own — and the packs no
longer read every picture at every start.

- **The game makes its own folders on Android** (`AndroidCorner`, from
  `Lifecycle` before the autoloads that read them). The first push had
  made `skin/` and `cardpacks/` from the shell, and a folder made with
  `adb shell mkdir` is the shell's — `rwxrws--- shell` — which the
  game, another Android user, may not enter: it saw an empty corner and
  one engine error from a listing that would not open, while the files
  inside were readable all along. Now the four folders (`skin/`,
  `cardpacks/`, `portraits/`, `music/`) are made at every start with a
  README in each, before anything is pushed into them.
- **The game says what it sees.** At every Android start the log
  (`adb logcat | grep -iE "godot|shandalar"`) carries `android: corner
  …`, one line per folder — `ok` with what it holds, `missing`, or `NOT
  LISTABLE` with the cure — the display's side (window, touchscreen,
  handheld word, pads), and then the first input event of each class
  once, with its device: how the headset's laser reaches the game, which
  is what the pointer work turns on. A listing that will not open no
  longer errors in `SkinPack`, `PortraitLibrary` or `MusicLibrary`.
- **Sealed card packs** (`PackSeal`). Every start hashed every picture
  of every pack against the manifest — 600 MB through the zip reader,
  7.5 s on a desk and the better part of a minute on the headset ("time
  is spent on card pack found"). A pack whose pictures passed once is
  sealed by its fingerprint (the file size and the zip's central
  directory, `user://pack_seals.json`, at most 64), and at the next
  start the manifest's word for the artwork digest stands without a
  picture read; the file list, the no-scripts rule, the metadata digests,
  the counts and the checklists still run. A pack rebuilt, repaired or
  replaced has another table and is hashed in full again. The discovery
  line says which: `card pack: found … (sealed)` or `(hashed)`.
- **`push_to_quest.sh` in the meta-quest package**: installs the APK,
  starts the game once when its folders are not there yet so that the
  game makes them, then pushes `skin/*.zip` and `cardpacks/` into them.
  The README names it; `docs/handhelds.md` has the Linux adb install
  (packages, the udev rule, `no permissions` against `unauthorized`),
  the by-hand order, the folder-ownership rule with its `ls -ld`
  signature, and the log lines to read.
- No wire change: protocol 24 peers interoperate.
