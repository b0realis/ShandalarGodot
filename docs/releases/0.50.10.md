# Shandalar 0.50.10

What a second code review — of 0.50.9 — found, fixed.

- **LAN discovery on the Meta Quest.** Godot's Android runtime takes the
  Wi-Fi multicast lock (without it the Wi-Fi drops broadcast packets)
  only for a socket with broadcast enabled, and only when the manifest
  declares CHANGE_WIFI_MULTICAST_STATE. The preset now declares it, and
  both ends of the Game Browser's discovery enable broadcast — the host's
  socket, which receives the browsers' queries, never did. 0.50.9's note
  that Godot takes no such lock was wrong. Untried on the headset.
- **`build_release.sh --quest` checks the APK's manifest** (aapt): an
  APK that does not ask for INTERNET, the network/Wi-Fi state and the
  multicast state is refused, with the lines to copy — a machine's own
  `export_presets.cfg` may be older than the published example.
- **One home-folder guard.** `tools/package_release.py --guard PATH...`
  is the packager's guard on the command line (exit 0 clean, 1 a home
  path, 2 unreadable). The release script's stages and the Quest APK both
  go through it, so every spelling of the home and the members of every
  zip (the skin zip too) are read everywhere; the stage grep for the
  literal `$HOME` bytes is gone. A damaged APK is "could not be read",
  not a leak. A user name cut by a read block's edge ("/home/anna"
  against the home "/home/ann") is no longer reported as the home.
- **Tests that can fail.** `--quest` runs end to end with a stub Godot
  and SDK (clean, a home path in a deflated member, an unreadable APK, a
  manifest without the network); the presets are read once, by name.

Gate: Python and the touched GUT scripts green (see the commit).
