# Shandalar 0.50.3

The first report from the ArkOS experimental build, an R36 Ultra: the
launcher refused to start on a full system drive, the 3.5-inch sidebar
card wants a key to read it, and a handheld without keys wants a
keyboard.

- **The launcher on a full drive.** Bash writes every here-document and
  here-string to a file under `TMPDIR` — `/tmp` on a system partition
  that was at 100 % — so PortMaster's `control.txt` came up half-read
  and the launcher blamed a missing controller mapper that was installed
  all along. `packaging/handhelds/arkos.sh` now keeps every temporary
  file beside the game (`shandalar/tmp`, removed on exit; the cache under
  `conf/cache`), splits PortMaster's commands in the shell without
  here-strings, runs an installed `gptokeyb` even when `control.txt`
  could not export it, writes a *"system drive is full"* line to
  `portmaster.log` when `/tmp` has under a megabyte free, and names a
  missing mapper before anything mounts. Four more launcher tests.
- **Read the card.** A new action, `R` on a keyboard, the right stick's
  press on a pad, R2 on ArkOS: the sidebar's card full-size in the duel
  and the Deck Builder, whether or not *Full-screen card on click* is
  on; the same key closes it. Nothing moves under it; it waits under the
  pause menu, a dialog or the Deck Builder's menu. Options → Controls
  rebinds it; the ArkOS mapping moves the duel log to L2 and mute to R3.
- **The on-screen keyboard.** Options → Display → *On-screen keyboard*:
  a board of keys across the window whenever a text field takes the
  focus, each key one real key event to the field — `Shift` for one
  key, `Enter` submits and puts the board away, `Done` puts it away, a
  click on the field brings it back; a physical keyboard still works
  beside it. `Auto` shows it on ArkOS and a Steam Deck, never on Android
  (the system's own) and never at a desk.

Gate: 550 scripts, **8,294 tests, 394,895 asserts**, exit 0
(264 s); Python 419 (5 skipped).
