# Shandalar 0.50.9

What a code review of 0.50.8 found in the release tooling, fixed.

- **LAN play on the Meta Quest.** The `Android Quest` preset asked for no
  permissions, so the APK declared none (`aapt dump permissions`), and
  Android refused SGManalink every socket — host, join, discovery and
  tournaments were offered and could not work. It now asks for INTERNET,
  ACCESS_NETWORK_STATE and ACCESS_WIFI_STATE (normal permissions, no
  prompt); a check export confirms all three in the manifest. Reinstall
  the APK. The Game Browser's discovery is untried on the headset (see
  `docs/handhelds.md`); an invitation always works.
- **The home-folder guard reads inside an APK.** 4,866 of the Quest
  APK's 4,940 entries are deflated, so a grep of its bytes could not see
  a path written in one. `package_release.guard_private` now opens every
  member of an `.apk` (and refuses an `.apk` that is not a zip), and
  `build_release.sh --quest` runs it on the APK it built.
- **The presets are pinned by name.** The release script's presets
  (Linux 64, Web, macOS, Android Quest) must all be in
  `export_presets.cfg.example` — a count could not notice the Quest
  preset missing, which it was from 0.40.48 to 0.50.8.
- **Docs:** the preset comment names the real key loader
  (`build_release.sh --quest`, not a `build_quest.sh` that never
  existed); CODE_MAP's Quest row and file tree; eight export targets,
  not seven.

Python: test_build_release_sh, test_package_release, test_tracked_tree —
49 tests, OK. No engine, card or game change.
